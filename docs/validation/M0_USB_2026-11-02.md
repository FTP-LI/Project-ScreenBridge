# M0 USB 验证记录（2026-11-02）

## 当前结论

已制作可构建、可签名安装的最小原型，并实测平板响应配件协议版本 2、成功切换到配件身份。用户在平板确认公开 API 已打开配件。Windows 在新身份下报代码 28，初次回传尝试未能打开 USB 设备，校验通过帧数为 0。

因此，已经跨过固件握手、模式切换和应用打开配件的关口，尚不能宣布完整双向回传或免安装方案成立。用户尝试系统 WinUSB 绑定后反馈“无法选择或安装失败”，具体界面错误尚未取得；随后用户按 Escape 停止了电脑界面操作，未再操作设备管理器。M0 整体未完成。

| Windows 新身份驱动 | 问题码 28，无 Service、INF、Provider；兼容 ID 列表未见 `USB\MS_COMP_WINUSB` | 本机这一身份未自动绑定驱动 |

`list` 基于 libusb，可访问设备为空不等于 Windows 没有枚举设备；PnP 结果才确认了新 USB 身份和无驱动状态。[after-start.json](results/2026-11-02-after-start.json) 保留这一差异。

构建最初显式配置 `compileSdkVersion: 26.0.0(26)` 被新 DevEco 拒绝；按构建器提示移除，采用内置 SDK。最终构建仍见模块 SemVer 警告（模块源码 version 为 0.1.0），需在发布前排查；不影响本次签名安装。

## 用户授权的实验例外

用户明确允许：仅在当前开发机为 `18d1:2d00` 尝试绑定 Windows 自带 WinUSB，以继续通信实验。此授权不代表接受最终产品必须安装驱动。

不修改正常调试身份 `12d1:5000`，不替换显示驱动，不关闭驱动签名检查，不启用测试模式。设备管理器自动点击未生效，已请用户在确认硬件 ID 后选择系统 `C:\Windows\INF\winusb.inf` 的 WinUsb Device。

微软说明 WinUSB 自动绑定依赖相应的设备 OS 描述符/兼容 ID；本机的实际枚举没有自动完成这一过程。其他电脑是否会已有匹配驱动必须另测，不能把这一次失败推广为所有方案都不可能免装。[微软 WinUSB 自动安装说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/automatic-installation-of-winusb)

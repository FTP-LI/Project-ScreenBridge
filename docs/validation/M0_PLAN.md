# M0 本轮实施范围

2026-11-02，按用户要求直接开展技术验证。

1. 核对本机工具、实际平板系统属性和 USB 枚举。
2. 通过原生 USB 控制请求查询配件协议；HDC 仅用于部署和诊断。
3. 制作 Python/PyUSB 主机探针和原生 ArkTS 配件回传应用。
4. 先测试协议的边界、分片、校验和超时，再构建应用、尝试真机部署和收发。
5. 分别记录源码测试、构建、部署、模式切换、真机回传结果。未做项目保持待验证。

实验帧：`SBP1`（4 字节）+ 序号、负载长度、负载 CRC32（各 4 字节，小端）+ 负载。负载最多 65,536 字节。平板检查后逐字节回传，电脑再次检查序号、CRC 和内容。CRC 只用于传输错误检测，不提供身份认证。

Windows 为 USB host，平板为 accessory device。主机先请求协议版本，再显式切换配件模式；扫描不改变设备模式。使用公开的 USB accessory API 和文件描述符读写，不使用 HDC 转发，不安装或替换 USB/显示驱动。应用先在前台手动授权启动。

本轮不包含视频、虚拟显示器、自动唤起、30 分钟稳定性和两类端口各 20 次插拔验收。签名和新 USB 身份的驱动绑定都是需要实测的关口。

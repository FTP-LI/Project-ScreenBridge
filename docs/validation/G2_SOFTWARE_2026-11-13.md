# G2 软件轨验证记录（2026-11-13）

## 本轮完成

本轮完成了 G2 软件骨架和 U3 生命周期收尾：

- `HostSession` 停止、超时和拔线后释放旧传输，下一次 `ready` 会打开新的 transport。
- PnP 工作线程无事件时永久等待，不再每 50 ms 唤醒。
- `DeviceWatch` 事件可以转发到会话编排入口。
- 新增 `HelperRuntime`，接入配对存储、PnP 事件、会话和 AOA 回调；握手异常会停止当前会话，不杀死事件路径。
- AOA 调试身份切换到配件身份时允许 PnP key 变化，仍拒绝未配对和歧义设备。
- 纳入 U4 实测正常身份 `12d1:107e`：驱动问题码非零或接口缺失时进入 `needs_setup`，不会盲发 AOA；接口恢复后复用同一握手路径。
- 新增 `WinUsbTransport`：包含接口路径唯一选择、读写、关闭幂等和 Windows overlapped I/O 的原生后端；单元测试使用注入后端。
- `WinUsbTransport` 增加 overlapped `WinUsb_ControlTransfer`；U4 开发机实测标准用户 `GET_PROTOCOL` 返回 2，AOA START 完成后设备重枚举。
- `HelperRuntime` 在配件接口到达且已进入 `waiting_tablet` 时启动控制帧读取，收到 `SBC1 ready/stop` 后关闭控制句柄并交给会话建立或清理；注入式回归覆盖该交接。
- `create_runtime()` 可建立默认 PnP/WinUSB/SessionMachine/HostSession 链路，当前仍是 Python 验证入口。
- 配对文件默认改为 `%LOCALAPPDATA%\\ScreenBridge\\pairing.json`，源代码运行且无该环境变量时才回退到仓库 `work/`。

## Windows API 冒烟

`create_runtime()` 使用真实 `CM_Register_Notification` 和设备枚举完成启动/停止；本轮只读观察到：

```json
[{"vid":"12d1","pid":"107e","problem_code":39,"interface_present":false}]
```

第一次只读观察表示关闭 USB 调试后当前会话能看到实测正常身份，但 Huawei 复合过滤驱动没有加载，运行时进入 `needs_setup`。随后使用临时开发绑定恢复接口，标准用户的 WinUSB 控制传输返回协议版本 2，AOA START 完成并重枚举为配件身份；完整证据见 [G1 报告](G1_USB_ACCESS.md)。

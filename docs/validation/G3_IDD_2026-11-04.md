# G3 屏桥显示器验证

记录日期：2026-11-04。

## 结论

屏桥自己的间接显示驱动可以在这台 Windows 11 上启动，并作为一块非主屏加入桌面。这不是 USB 画面，也不是 Todesk 或 GameViewer 的适配器。

先前代码 31 的原因是编译时没有定义 `UMDF_VERSION_MINOR=25`。驱动框架因此无法完成版本绑定，启动函数没有被调用。补上该定义后，问题码变为 0。

## 实测

| 项目 | 结果 |
| --- | --- |
| 设备 | ScreenBridge Display，问题码 0，INF `oem135.inf` 之后的更新包 |
| 适配器 | `\\.\DISPLAY101`，名称 ScreenBridge Display，已接入桌面，不是主屏 |
| 活动路径 | `DISPLAY101` 单独一条。物理屏仍在 `DISPLAY1`、`DISPLAY2`，目标名称为 V2719Q |
| 其他虚拟屏 | Todesk 与 GameViewer 适配器存在，但没有接入桌面 |
| 工具 | MSVC 14.44.35207，WDK/SDK 10.0.26100，UMDF 2.25，IddCx 1.6，扩展声明 `IddCx0102` |

驱动没有提供 EDID。活动路径查询到的目标友好名称为空。`EnumDisplayDevices` 在该适配器下还列出一个名称为 ACER S271HL 的子设备；这不是本驱动写入的名称。

## 图像交接

同一天的后续构建在取得第一帧后记录了尺寸和非零采样。结果为宽 `0x400`（1024）、高 `0x300`（768），采样的 8192 字节中有 `0x800`（2048）字节非零。活动路径为 `\\.\DISPLAY115`，目标友好名称仍为空。物理屏路径仍指向 V2719Q。

20:07 左右这块虚拟屏仍在，当时桌面枚举为非主屏 `\\.\DISPLAY129`，边界 1024×768。`work/idd-package/sb-frame.txt` 里另有一条 19:26 的采样，宽 `0x780`（1920）、高 `0x438`（1080）；它和当时的桌面尺寸不一致。

源码随后改为只上报屏桥自己的 1920×1080@60 EDID，驱动版本 `1.0.1.2`。该包已签名并安装为 `oem138.inf`，问题码 0。安装后的桌面枚举为非主屏 `\\.\DISPLAY143`，边界 1920×1080。这是屏桥显示器的桌面模式，不是 USB 画面，也还没有把帧交到用户进程。驱动仍只把第一帧的尺寸采样写到临时文件。安装后驱动在 2026-11-04T20:09:30 写出的采样为宽 `0x780`（1920）、高 `0x438`（1080），采样的 8192 字节中有 `0x800`（2048）字节非零，复制件在 `work/idd-package/sb-frame-now.txt`。

2026-11-05 上午复查时，宿主进程已不在，屏桥显示器和 `\\.\DISPLAY143` 都已消失，只剩两块物理屏。要再次出现需要重新以管理员身份运行宿主。

用户进程侧加了一个只保留最新一帧的 `FrameSlot`。2026-11-04 用 MSVC 14.44（Visual Studio 2022 Build Tools 17.14.44）编译并运行 `apps/windows/streaming/frame_slot_test.cpp`，退出码 0：空槽无帧、新帧替换旧帧、越界和长度不符会被拒绝。复现命令是在该目录执行 `vcvars64.bat` 后 `cl /nologo /EHsc /W4 /std:c++17 /Fe:frame_slot_test.exe frame_slot_test.cpp`。这不是驱动到用户进程的交接，也没有新的实机帧。

签名仍是本机自签证书，不是公开发布签名。

## 2026-11-06 状态复查

只读检查：屏桥显示器未接入桌面，`ScreenBridge Display` 设备记录状态为 Unknown；驱动库里保留多个旧版本 IDD 包（`oem122.inf` 至 `oem138.inf`），签名者都是本机自签 `ScreenBridge Development`。2026-11-06 的持续开发计划已授权清理这些废弃包；`scripts/windows/Clean-OldDisplayDrivers.ps1` 默认只预览，核对 Provider、原始 INF 与签名者后列出 11 个旧 IDD 包，默认保留 `oem121.inf`（USB）与 `oem138.inf`（当前版本）。当前 PowerShell 会话不是管理员，且本机执行策略为 Restricted（需进程级 `-ExecutionPolicy Bypass`），因此尚未执行 `-Apply`，驱动库仍是 13 个 ScreenBridge 包。

用户进程的 `FrameSlot` 源码仍在仓库中，编译测试已通过；驱动仍只把第一帧的尺寸采样写到临时文件，驱动到用户进程的图像交接没有实现。

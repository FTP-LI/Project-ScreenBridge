# 项目目标与需求记录

记录日期：2026-11-02。本文整理当前讨论结论，供换电脑后继续开发；不表示架构已经定案或原型已经通过测试。

## 用户明确提出的需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R01 | 华为平板作为 Windows 电脑扩展屏 | 两块屏幕可显示不同窗口，不能只实现主屏镜像 |
| R02 | 使用有线连接 | 当前优先研究普通 USB 数据线连接 |
| R03 | 同时支持有 PD 和无 PD 的电脑 USB 接口 | 两种情况均要验证；PD 不是数据通道的前提 |
| R04 | 尽量接线即可使用 | 允许平板安装应用，期望减少日常操作 |
| R05 | 电脑一次配置，之后日常免配置 | 用户最新明确接受电脑配置一次后无需反复配置；允许必要配套组件，具体安装、签名、跨端口保留仍需验证 |
| R06 | 考虑自行开发并发布 | 目标包括正常分发和普通用户可用，不仅是开发环境中的演示 |
| R07 | 能换电脑继续开发 | 当前目标、状态、资料和后续任务应在 Git 仓库中保存 |
| R08 | 从平板发起，电脑自动识别为扩展屏 | 用户明确反对日常先在电脑执行 `start`、再执行 `echo` 的流程；开启平板功能后，电脑应自动响应，无需手动命令或反复切换两端操作 |
| R09 | 电脑允许低占用后台监测 | 用户接受常驻监测，待机应尽量节省资源，编码传输按会话启动；实际占用需测量 |

R05 更新于 2026-11-02：早期偏好是电脑最好免安装；用户现已接受一次性配置和低占用后台。这是新的部署要求，不应继续沿用旧文档中“首次安装仍待用户确认”的结论，也不代表任何驱动已经安装成功。

## 当前已知设备

- 平板：华为 MatePad Pro 12.2。
- 平板系统：用户原先提供为 HarmonyOS 7；本轮 HDC 属性为 API 24 / OpenHarmony-6.1.1.120，软件版本 MRO-W00 6.1.0.135(SP9C00E125R1P4)。详见[验证记录](validation/M0_USB_2026-11-02.md)。
- 电脑：前期讨论为联想；本轮实际开发机为七彩虹 B850M 主板、Windows 11 x64，不能把当前结果直接算作联想兼容通过。
- 当前数据线已用于 HDC、原生控制请求和配件重枚举；接口形式、PD 和实际数据速率仍待核实。
- 用户要求同时覆盖支持 PD 和不支持 PD 的电脑 USB 接口。不能据此认定已经具备两类测试端口。

此前用户允许在当前开发机为 `18d1:2d00` 配件身份临时绑定 WinUSB 做通信实验；最新的产品部署原则已更新为 R05/R09。具体 USB 和显示驱动安装结果仍以验证报告为准。

## 使用体验目标

1. 首次通过一个配置入口完成必要组件安装、授权、配对和自检；正常使用不重复配置，跨端口和重启的保留效果需验收。
2. 使用时通过数据线连接，形成独立扩展桌面；不依赖无线网络传输画面。
3. 用户继续使用电脑键盘和鼠标，把窗口拖到平板显示。
4. 拔线后，电脑的主屏和显示布局可恢复，重要窗口不会长期留在不可见区域。
5. 供电不足时允许使用平板电池；支持 PD 也不承诺必然实现边用边充。

### 本轮体验纠正（2026-11-02）

用户期望的日常流程是：**连接 USB → 打开平板屏桥或启用扩展 → 电脑自动出现可扩展的第二块屏幕**。必要的首次授权另行说明。电脑端 `start` / `echo` 仅为 M0 开发诊断命令，不能成为成品的使用前提。

这里的“识别”必须以 Windows 显示设置中出现独立显示器、可使用扩展桌面为准。出现 USB 配件、打开配件句柄或完成 echo 都不足以满足 R08。

用户操作从平板发起，不代表 USB 底层请求必须由平板发起。当前 AOA 路径的模式切换请求由电脑端发出；若保留此路径，由电脑后台自动处理握手，平板启用状态决定是否开始显示会话。一次配置和低占用后台已获接受，具体实现建议见[推荐方案](RECOMMENDED_APPROACH.md)。当前原型没有后台自动发现，也没有虚拟显示器实现。

当前验收重点是一次配置后无需日常电脑操作，不再要求电脑完全没有配套程序或驱动；仍应准确说明首次安装的组件和权限。

“自动连接”分开记录三个场景：

- 应用已打开、平板已解锁并已授权时，插线建立连接。
- 应用未运行时，插线唤起应用并连接。
- 平板锁屏或电脑休眠后，恢复连接。

这三个场景的难度和系统限制不同，不能用第一个场景的成功代替全部自动连接能力。

## 建议的首版范围

以下是讨论中提出的实施建议，仍可按验证结果调整：

- 先以用户现有平板和 Windows 电脑为验证设备。
- 单台电脑连接一块平板，先做横屏扩展桌面。
- 基础连接状态、错误提示、分辨率与码率设置、断线恢复和诊断日志。
- 首个性能目标为 1920×1080、60 FPS；这是目标，不是当前能力或所有设备的保底规格。
- 将 USB 2.0 和 USB 3.x 的实际表现分开测试，不以 PD 标识推断带宽。
- 首版暂缓手写笔压感、触屏反控、多平板、4K 高刷新率、HDR 和跨互联网远程使用。

## 尚未解决的关键问题

| 问题 | 需要获得的证据 |
| --- | --- |
| 普通鸿蒙应用是否能建立所需 USB 直连通道 | 目标设备实测、准确的 SDK/API 版本、权限和 Windows 侧配合要求 |
| Windows 能否在可接受的安装条件下创建扩展屏 | 虚拟显示器枚举、独立桌面显示，以及驱动安装与分发要求 |
| 一次电脑配置能否覆盖日常连接 | 跨端口、重启和升级后正常识别；日常不重绑驱动、不重配参数、不要求手动启动助手 |
| 低占用监测是否成立 | 无设备/已连接待机的 CPU、内存和唤醒记录，画面处理资源按需释放 |
| USB 插入能否自动启动或恢复平板应用 | 应用前台、后台、未运行、锁屏状态的独立测试 |
| 普通数据线能达到什么效果 | 线材、端口、数据速率、丢包/错误、解码与端到端延迟测量 |
| 所用能力能否用于正式发布 | 目标设备类型、公开接口、权限和应用分发要求核对 |

## 方案边界

- 当前推荐主线是自研普通 USB 通道、Windows IDD、低占用助手和原生鸿蒙应用；USB 实验已有 SDK 和 Python/ArkTS 选型，产品实现建议及未验证关口见推荐方案。
- Windows 显示驱动作为一次电脑配置的候选组件继续验证；用户已接受部署原则，实际包的签名、安装和独立扩展仍需实测。
- USB 网络共享可以用作单独的备选或对照实验。必须注明手动开关和网络配置，不能把它记录成原生 USB 直连成功。
- 采集卡加平板应用是曾讨论的备选，不是当前默认硬件方案。
- Moonlight、Sunshine、spacedesk 是前期调研对象；本工程未决定基于它们开发，也没有集成相关代码。
- 不承诺零延迟、所有机型通用、PD 必然充电或插线必然自动启动应用。

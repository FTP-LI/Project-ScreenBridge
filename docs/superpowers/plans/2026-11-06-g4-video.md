# G4 第一条可用画面链路实施计划（S4）

> 状态：**等待放行关口 P4**，不得提前实施。P4 = G1 四个独立结论字段 + G3 标准用户连续读帧 + G2 真机自动会话，三者齐备。契约见 `docs/CONTRACT.md`。

**Goal**：平板打开屏桥后，电脑自动出现可显示不同窗口的独立扩展屏；先 1080p30 功能样机，再到 1080p60 目标；拔线自动移除屏幕并恢复布局。

**Architecture**：IDD 帧（S2 交接）→ GPU 硬件 H.264 编码 → `SBV1` 分片 → `SBP1` 帧 → WinUSB OUT → 平板 `FrameDecoder`/`VideoAssembler` → 原生解码 → Surface/XComponent 显示；关键帧与会话就绪后才挂屏，失败回滚。

## 步骤

- [ ] 核对 P4 三项证据齐备，未齐备则停在软件准备，不提前挂屏或宣布链路通过。
- [ ] 先用**已知测试码流**验证平板解码与显示，再接 Windows 硬件编码与 IDD 帧；不要先假设编码可用。
- [ ] 实现 Windows 编码封装与 `split_access_unit` / `encode_capability` / `encode_stop` 调用方；把 `run_echo` 的回环语义改为单向流式发送，控制类型、帧边界、时间戳与有界缓冲按 CONTRACT.md 对齐。
- [ ] 平板端把 `VideoAssembler` 输出的完整帧送解码器与 Surface，替换 `noteVideo` 的纯计数；`module.json5` 补权限；用 DevEco 内置 SDK **重新构建并签名安装**（现装 HAP 无此代码）。
- [ ] 会话就绪 / 关键帧到达后才报告显示器接入；编码初始化失败、平板未就绪、能力不匹配都回滚；停止或拔线移除显示器并释放编码器、纹理、传输队列。
- [ ] 覆盖慢接收、关键帧恢复、CRC/长度错误、应用退后台；旧画面不无限堆积。
- [ ] 记录帧率、延迟测量方法、CPU/GPU/内存/USB 负载与丢弃/错误帧；**不把 echo 往返速率换算成视频 FPS**。

## 验收

- 平板打开屏桥后电脑自动出现**不同桌面**的独立扩展屏（非镜像）；键鼠可跨屏。
- 1080p30 功能样机先行，再优化到 1080p60 目标；两者都是目标，未实测前不标为能力。
- 拔线自动移除屏幕、主屏与窗口布局恢复；无失联显示器。
- **禁止**：用 HDC 转发、USB 网络共享、采集卡或第三方虚拟显示适配器替代；把协议层测试或 IDD 独立接入写成完整画面链路通过。

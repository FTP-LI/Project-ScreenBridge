# 阶段目标与验收路线图

记录日期：2026-11-02。

以下是项目路线图。M0 已开始，具体进展见[验证记录](validation/M0_USB_2026-11-02.md)。所有未勾选验收项仍为目标；尚无整体通过的阶段。

## M0 技术可行性验证

目标：回答普通 USB 直连能否成立、电脑必须安装什么，以及自动连接能做到哪一步。

- [ ] 记录参考电脑、平板、系统构建号、线材和端口能力。
- [ ] 核对目标 HarmonyOS SDK 的公开 USB 接口、授权方式及设备支持范围。
- [ ] 明确两端的 USB 角色、枚举方式和通信协议，不只凭接口名称推断能够互通。
- [ ] 制作最小通信原型，检查双向数据、校验结果和持续传输能力。
- [ ] 分别通过有 PD、无 PD 的 USB 数据端口持续测试 30 分钟。
- [ ] 完成两类端口各 20 次插拔测试，记录成功率、恢复时间和重新授权要求。
- [ ] 验证 Windows 创建独立扩展屏的路径，列清安装、管理员权限和正式签名需求。
- [ ] 分别检查平板应用前台、后台、未运行和锁屏时的连接行为。
- [ ] 输出可行性结论、证据、限制和下一阶段架构建议。

建议验收规则：持续传输的测试数据校验一致，无未恢复的挂起；吞吐率和错误均有记录。通信实验和 Windows 扩展屏实验分别记录，未连通完整链路时不能宣布产品已可用。

交付物：通信原型、复现步骤、测试记录和可行性结论。测试记录后续放在 `docs/validation/`，包含设备与软件版本、步骤、预期、实测、日志位置和结论。

如果公开接口无法满足关键要求，先形成明确结论，再选择一次安装驱动、USB 网络共享或硬件配件等替代方向。不能在未说明取舍的情况下替换产品目标。

## M1 个人可用版本

前提：M0 提供足够证据，Windows 安装条件和通信路径已经确定。

- [ ] 实现 Windows 扩展显示输出、画面编码、USB 传输和鸿蒙解码显示的完整链路。
- [ ] 电脑和平板能同时显示不同窗口，键鼠可跨屏操作。
- [ ] 以 1080p、60 FPS 为首个性能目标，记录实际帧率、延迟、画质和资源占用。
- [ ] 支持基础画质设置、连接状态、错误提示和断线恢复。
- [ ] 在两类参考端口上连续使用 2 小时，无崩溃或无法恢复的断线。
- [ ] 验证拔线后的主屏、窗口和显示布局恢复。

交付物：供个人设备试用的版本、安装运行说明及两类端口的测试报告。

本阶段的自动连接最低目标是“应用已打开、平板已解锁、已授权时插线连接”。其他自动唤起场景必须标注实际支持状态。

## M2 公开测试版本

目标：让其他用户可以安装、使用并反馈问题。

- [ ] 简化首次安装和授权，明确线材与接口要求。
- [ ] 改善自动重连、电脑休眠恢复、平板锁屏恢复和多显示器布局处理。
- [ ] 建议覆盖至少 3 款平板、5 种电脑配置；实际测试设备需要另行筹集。
- [ ] 在兼容记录中分别列出 PD 能力和 USB 数据速率，覆盖有 PD、无 PD、USB 2.0 和 USB 3.x 的实际组合。
- [ ] 形成支持列表、已知问题、诊断方式和反馈模板。
- [ ] 检查安装、升级、卸载后的显示状态和残留组件。

交付物：公开测试包、兼容性矩阵、更新记录和问题反馈说明。

## M3 正式发布

目标：普通用户可以正常获取、配置和持续使用产品。

- [ ] 核实鸿蒙应用所用接口、权限和发布要求。
- [ ] 如需 Windows 驱动，验证正式签名、分发和升级流程。
- [ ] 确保正常运行不依赖 HDC、调试连接或系统测试模式；开发阶段部署手段另行记录。
- [ ] 完成安装、更新、卸载、帮助与故障恢复流程。
- [ ] 核查依赖许可证、项目名称和分发方案。
- [ ] 发布说明只列已验证设备和能力，并明确限制。

交付物：正式分发包、用户文档、版本记录和维护流程。

## 当前进度

- 已完成：环境检查、选定系统属性读取、原生 USB 配件握手、模式切换、最小原型源码与协议测试、HAP 构建及开发签名安装。
- 用户实机反馈：平板公开 API 已打开配件；Windows 新配件身份报代码 28。经用户授权尝试系统 WinUSB 绑定，用户反馈无法选择或安装失败，具体错误待取得。
- 尚未通过：完整双向校验、长测、两类端口插拔、前后台/锁屏恢复、Windows 扩展桌面和发布审核。不能用已有软件测试与握手结果替代这些验收。

# 屏桥实现目标规划 / Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task; use superpowers:subagent-driven-development only when the user has chosen delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 电脑一次配置后，插入普通 USB 数据线并打开平板屏桥，即可自动建立真正的 Windows 扩展桌面；停止或拔线后自动恢复等待。

**Architecture:** Windows 事件驱动助手负责发现设备和连接控制；WinUSB 承载原生 USB 数据；IDD 提供独立显示器；GPU 编码后的画面由鸿蒙应用解码显示。无显示会话时只保留低占用监测。

**Tech Stack:** 当前实验为 Python 3.12.10 / PyUSB 1.3.1、ArkTS、DevEco 内置 API 26 SDK；计划中的 Windows 正式组件首选 C++、WinUSB、UMDF/IddCx、硬件 H.264 编码；平板使用公开配件 API 和系统原生视频解码。

**Spec:** [已选实现主线](RECOMMENDED_APPROACH.md)、[用户目标 R01–R09](PROJECT_GOALS.md)。用户于 2026-11-02 选定主线并要求规划；下列代码、性能与安装结果尚未取得。

## Global Constraints

- 首版限定当前 Windows 11 x64 和当前参考平板，不据此承诺其他 Windows 版本/架构兼容。
- 普通 USB 数据线；同时覆盖有 PD、无 PD 的数据端口，不以 PD 判断数据能力。
- 电脑首次一次配置，日常无需命令、重绑驱动或重新配对；允许低占用后台监测。
- 平板应用前台、已解锁、首次授权完成为第一版前提；后台、未运行、锁屏另行记录。
- 不用 HDC 转发替代原生 USB，不借用第三方虚拟显示适配器证明屏桥成功。
- 安装与发布使用正常签名机制；保留 GNU AGPL v3，签名材料和设备个人标识不入库。
- 所有数字为验收目标，未通过前不得标为产品能力；当前证据见[验证报告](validation/M0_USB_2026-11-02.md)。

## 当前基线

已存在 `prototypes/usb/`、`drivers/windows/` 的 WinUSB 与 IDD 源码、`apps/windows/` 的连接状态机、`shared/protocol/` 的视频分包，以及签名平板应用。2026-11-04 已在配件身份 `18d1:2d00` 上取得真机 echo 证据：100 帧、140 帧边界、重开后 140 帧、60 秒 11782 帧。2026-11-06 本机自动化基线为 Python 23+27+7 项、Node 6 项全部通过；这些是假端点与本地协议测试，不是真机验收。代码 28 与更新向导取消属于 11-02 的历史记录。细节见 [G1_USB_ACCESS.md](validation/G1_USB_ACCESS.md) 和 [G3_IDD_2026-11-04.md](validation/G3_IDD_2026-11-04.md)。

当前开发机不是前期提到的联想电脑；PD、线速和两类参考端口仍未确认。开发机为七彩虹 B850M、Windows 11 10.0.26200；2026-11-04 当天已补齐 MSVC 14.44、WDK/SDK 10.0.26100 与 INF/签名工具，USB 包与 IDD 包都是本机自签，不是可公开发布的签名。2026-11-06 只读复查时没有在线的 `12d1`/`18d1` 设备，`hdc` 未运行，屏桥显示器也未接入；不能把历史记录当成设备仍连接或驱动已验证完成。

## 里程碑与依赖

| 目标 | 交付物 | 通过标准 | 依赖及下一步 |
| --- | --- | --- | --- |
| **G1：USB 通道成立** | 环境清单、WinUSB 包来源/签名说明、双向校验记录、非调试起连报告 | 标准用户能访问接口；真实数据一致；关闭 HDC/调试后可从日常模式进入配件态 | 从当前代码 28 开始；失败则先解决 USB 路径，不宣布主线连通 |

| **G3：真正的独立显示器** | 可构建的屏桥 IDD、可追溯签名与安装记录、显示配置证据 | Windows 能列出屏桥显示器并设为扩展，可容纳独立窗口；显式挂载/卸载不破坏其他屏幕 | 驱动工具/签名检查后可独立实验；集成受 G1/G2 约束 |
| **G4：第一条可用画面链路** | IDD 图像交接、H.264 编码、USB 视频传输、平板解码、会话启停 | 连接并打开平板应用后自动出现不同桌面；先达 1080p30 功能样机，再优化至既定 1080p60 目标；拔线自动移除屏幕 | G1+G2+G3；30 FPS 是中间检查点，不降低 60 FPS 目标 |
| **G5：一次配置与日常免配置** | 单一电脑安装/诊断/卸载入口、登录自启、首次配对、签名包与恢复流程 | 重启、换端口无需重绑；日常无需管理员或命令；升级/卸载后状态正确 | 组件安装验证从 G1/G3 开始，G4 后整合；不能将签名问题留到临发布才发现 |
| **G6：稳定性与发布准备** | 兼容矩阵、性能与恢复报告、低占用记录、试用包/发布检查 | 两类端口各 30 分钟和各 20 次插拔；个人版本两类端口各连续 2 小时；不遗留失联显示器 | G4/G5；其余版本和机型按 M2/M3 扩展，不先承诺支持 |

优先执行 **G1 → G2 → G4 → G5 → G6**；G3 在工具和签名条件明确后独立推进，与 USB 验证共享最终集成入口。开发队列可调整，但 G4 必须等待 G1/G2/G3 的真实证据。

### G2：连接控制和后台

计划目录：`apps/windows/helper/`、`tests/windows/helper/`；原生鸿蒙应用正式目录：`apps/harmony/screenbridge/`。实验目录继续保留，不直接把 Python CLI 当成后台产品。

- [ ] 形成独立实施计划后，先实现可注入事件的连接状态机，再接 Windows PnP 与 WinUSB。2026-11-04 已有会话模型和先订阅再枚举的监听。同日只读枚举看到当前配件 `18d1:2d00`，问题码 0，屏桥接口存在；没有打开 USB，也没有把它当成自动连接通过。同日把这块未配对配件送入会话后，动作是 `reject_unpaired`，阶段保持 `disconnected`，打开次数为 0。到达通知会在回调外再读问题码和接口，拔出仍只按设备键清理。假传输上，平板未就绪不会打开通道，就绪后只打开一次，打开失败会收回显示，移除当前设备只关闭一次。真机热插拔和真实 WinUSB 打开都还没验证。
- [x] 状态至少覆盖未连接、等待重枚举、等待平板、建立会话、运行中、清理和需要首次配置；同一时刻只允许一个目标会话。2026-11-04 由 `test_required_phases_allow_only_one_session` 覆盖。这不是真机自动连接。
- [x] 先注册通知，再枚举已有设备；验证晚启动和重复通知去重。2026-11-04 由 `tests/windows/helper/test_device_watch.py` 用假总线覆盖。真机 PnP 尚未接入。
- [x] 设计显式的能力/就绪/停止控制消息，验证版本不兼容、授权拒绝、错误配件、平板未打开时不会继续投送数据。2026-11-04 消息格式为 `SBC1`。假传输上，坏帧、版本不符、未授权、能力查询和未配对都不会打开通道；停止会关掉已打开的传输。平板还没有发送这些消息。
- [ ] 为阻塞读写、设备移除和退出设计取消及有限超时；用假传输覆盖停止竞态，再用真机验证。2026-11-04 假传输已覆盖：停止会在超时前打断等待中的读取，已完成的帧保留，移除当前设备只关闭一次。尚未接到 WinUSB，也没有拔线实测。

### G3：Windows 显示子系统

计划目录：`drivers/windows/display/`、`tests/windows/display/`；应有自己的构建、安装及显示验证说明。

- [ ] 在单独的显示实施计划中固定 WDK/SDK/编译器组合、驱动身份与受控接口。
- [ ] 先独立创建和移除屏桥显示器，核对显示器标识、扩展拓扑和可用模式。
- [ ] 验证图像获取、显卡适配器选择、驱动 Session 0 与用户进程间的受控图像交接，不预先承诺零拷贝。2026-11-04 用户进程有单帧槽并通过编译测试；驱动仍只写一次临时采样，实机交接未做。
- [ ] 检查双屏/多屏下的启停和布局保留；不把机器已有的 Todesk/GameViewer 适配器计入结果。

### G4：编解码与完整会话

计划目录：`apps/windows/streaming/`、`shared/protocol/`、`apps/harmony/screenbridge/`；三端接口必须在该阶段实施计划中固定。

- [ ] 先用已知测试码流验证平板解码和显示，再接 Windows 硬件编码及 IDD 图像。
- [ ] 视频协议覆盖控制类型、帧边界、分片、时间戳、能力协商和有界缓冲；不要直接假设 64 KiB 的 SBP1 实验帧足以容纳一个压缩视频帧。2026-11-04 `SBV1` 能把大于 65536 字节的帧拆进 SBP1，再经 SBP1 帧读回。未完成的旧帧会丢掉，丢帧后的差分帧要等到下一张关键帧。平板源码会在回传 SBP1 的同时识别其中的 `SBV1` 关键帧，本机 Node 测试已通过。已安装的应用没有这次代码，也还没有解码；编码器也还没有接上。
- [ ] 在平板解码能力与会话就绪后才报告显示器接入；失败回滚，停止/拔线移除显示器并释放资源。2026-11-04 会话在关键帧之前不标记显示器，打开失败不会标记，停止或拔出会清掉已标记的显示器。还没有真正创建 Windows 显示器，平板也还没有解码。
- [ ] 覆盖慢接收、关键帧恢复、CRC/长度错误、编码器初始化失败与应用退到后台；不无限堆积旧画面。
- [ ] 记录帧率、延迟测量方法、CPU/GPU、内存、USB 负载和丢弃/错误帧，不将 echo 往返速率换算成视频 FPS。

计划目录：`installer/windows/`、`scripts/windows/`；凭证和签名私钥仍只留本机。

- [ ] 单次安装完成必要驱动、设备接口、正常用户访问权限、登录自启和自检；安装中断时可回滚并重试。
- [ ] 区分管理员安装与日常标准用户运行，验证真正的标准用户场景。

- [ ] 验证两类端口、重启、换线/换端口后的配置保留；授权是否保留以实机结果为准。

### G6：验收与发布

计划目录：`tests/hardware/`、`docs/validation/`、`docs/releases/`。

- [ ] 空闲监测程序私有内存目标 ≤30 MiB；未插线稳定 10 分钟累计 CPU 时间目标 ≤0.6 秒（单逻辑核平均 0.1%）。记录工作集、驱动宿主和其他屏桥进程；连接待机也单独测量。
- [ ] 分别确认有 PD/无 PD 端口、USB 速率、线材和供电表现；每类端口持续 30 分钟、各 20 次插拔；两类参考端口的个人版本各连续 2 小时。
- [ ] 建议自动恢复目标：拔线/重插后不需重新配置；记录每次发现、握手和出画面时间；时间阈值待首条完整链路实测后设定，不编造延迟保底。
- [ ] 分别测试前台、后台、未运行、锁屏、电脑休眠；首版未覆盖的状态写入限制，不当成已实现自动唤起。
- [ ] M2 筹集设备覆盖（建议至少 3 款平板/5 种电脑）；M3 核实鸿蒙分发、Windows 正式签名和许可证、名称等发布条件。

## 证据和完成规则

每个目标必须附准确版本、设备/线材/端口、步骤、预期、实测、脱敏记录及复现命令。软件测试、构建、签名、安装、USB 握手、数据回传、虚拟显示与真实画面分别记账。

USB 正常模式无法通过可发布路径起连时，G1 结论应是该路径不满足目标，保留独立显示研究；改用 USB 网络或采集卡属于重新评估方案，不自动更换主线。签名或测试设备缺失时记录所缺条件，不能靠降低验收宣告完成。

本文的 G1–G6 是规划，勾选状态以各实施计划与验证报告为准。2026-11-04 已取得配件态真机回传和 IDD 独立接入的本机证据，2026-11-06 补齐软件测试基线并整合分支；这些都不等于自动连接、完整画面链路或扩展桌面通过。后续每个独立子系统在开始编码前写自己的实施计划；G1 的下一步已细化，其他阶段避免提前锁定尚无证据的底层接口。以门槛通过排开发顺序，暂不估算未经验证的日历工期。
